- (capability) CAP-3 Per-period allocation: set 0-100% allocation per role per planning period; unique per (plan, period); drives totals/effort.
- (capability) CAP-4 Real-time costing & margin: internal cost, client price, margin, estimated effort computed live via single-source calculations.ts (margin 0..1 internal / 0-100 persisted; exchangeRate client-per-USD applied internal*rate; divide-by-zero guarded).
- (capability) CAP-5 Global rate card management: import org-wide card from Excel (RMNG RATES sheet), edit/clear inline, regional internal rates per role; bulk import atomically replaces card + records import meta; shared across all projects; excluded from project copy/export/import.
- (capability) CAP-6 Resource roster (resource list): manage a project's roster of available roles/resources; seed roster from a rate-card role.
- (capability) CAP-7 Weekly/monthly planning: plan in weekly or monthly cadence and convert between them; conversion transforms phases + every allocation in a transaction (weeksPerMonth = daysInFTE/5) and returns the reloaded project.
- (capability) CAP-8 Client-facing view: present a cleaned-up client view of the plan's pricing (client roles/rates) without exposing internal cost detail.
- (capability) CAP-9 Export & import: export plan to Excel (phase-grouped + totals), export/import project as JSON ({schemaVersion,exportedAt,data}; legacy weeklyAllocations/weekNumber accepted on import; rate card never included), capture PNG snapshot.
- (capability) CAP-10 AI draft plan generation: from a NL project description + delivery region, produce an editable DRAFT resource plan (roles constrained to GlobalRateCard, per-phase allocations); previewed in the grid; rates resolved deterministically server-side; never persisted without explicit user acceptance; LLM provider pluggable via Vercel AI SDK + ai.config.ts (default Anthropic claude-opus-4-8).

- (constraint) Every write endpoint validates with a .strict() Zod schema (server-validation.ts); clients must strip server-managed fields (id/createdAt/updatedAt/relation IDs) or validation fails.
- (constraint) Three definitions must stay aligned per field: prisma/schema.prisma (storage) <-> server-validation.ts (.strict write shape) <-> src/services/api.ts (client TS interface). Frontend never imports Prisma; uses mirrored interfaces. Prisma client generated to src/generated/prisma.
- (constraint) Rate card is GLOBAL (single GlobalRateCard table + RateCardImportMeta singleton id=1), shared across all projects, intentionally excluded from project copy/export/import.
- (constraint) Pricing units are fixed: margin 0..1 inside calculations.ts but 0-100 when persisted/displayed (convert at boundary); exchangeRate = client-currency-per-USD applied as internal*exchangeRate; region slug (kebab e.g. eastern-europe) != DB column (camelCase easternEurope) and must be mapped.
